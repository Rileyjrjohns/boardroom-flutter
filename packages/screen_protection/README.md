# screen_protection

Local Flutter plugin of the Boardroom app (never published): blocks screenshots and screen recording of the app and reports attempts. Android: `FLAG_SECURE`, `Activity.ScreenCaptureCallback` (14+), the screen recording callback (15+). iOS: a cover in the app switcher, screenshot and recording detection, and a secure view that leaves its content out of captures. What it does, its limits and what was verified are in [`docs/native-module.md`](../../docs/native-module.md).

The app does not call it directly: `lib/features/documents/infrastructure/native` adapts it to the `ScreenProtection` port, and `lib/features/documents/presentation/secure_content.dart` is the one screen file that imports its widget.

| Path | What |
| --- | --- |
| `pigeons/screen_protection_api.dart` | The API of the channel, declared once |
| `lib/screen_protection.dart` | The calls and the events (for the adapter) |
| `lib/screen_protection_view.dart` | `SecureView`, the widget |
| `lib/src/messages.g.dart`, `android/.../Messages.g.kt`, `ios/.../Messages.g.swift` | Generated by Pigeon, committed |
| `android/` | Kotlin: `ScreenProtectionPlugin`, `ScreenProtectionHost`, the detectors, `ProtectionState`; JVM tests in `src/test` |
| `ios/screen_protection/` | Swift (a podspec and a Swift package): `ScreenProtectionPlugin`, `ScreenProtectionHost`, `ScreenProtectionSecureView`, `CaptureLogic`; XCTest in `Tests` |

## Regenerate the channel

After any change of `pigeons/screen_protection_api.dart`, from this folder:

```sh
dart run pigeon --input pigeons/screen_protection_api.dart
dart format lib
```

CI regenerates the files and fails on a difference.

## Tests

```sh
flutter test                                          # the Dart side, from this folder
cd ../../android && ./gradlew :screen_protection:testDebugUnitTest   # the Kotlin logic, on the JVM
```

The Swift tests (`ios/screen_protection/Tests`) run on an iOS simulator, with `xcodebuild test` on a project that uses the plugin.
