# 0004. A Pigeon plugin rather than a raw MethodChannel for ScreenProtection

- Status: Accepted
- Related: [0001](0001-feature-first-hexagonal-architecture-with-links-inverted-through-the-composition.md)

## Context

Confidential documents must stay out of screenshots, recordings and the app switcher as far as each platform allows, and the app must learn when a capture happens. No Flutter package does this, so native code has to be written: `FLAG_SECURE` and the capture callbacks on Android, a cover view, the capture notifications and an undocumented secure layer flag on iOS. In the React Native app this is a local Expo module. The Flutter port needs the same native half behind the same `ScreenProtection` port, and a channel between Dart and the two platforms.

## Decision

A local plugin, `packages/screen_protection`, in Kotlin and Swift, over a typed channel generated by Pigeon ([native module](../native-module.md)).

- **One declaration of the API.** `packages/screen_protection/pigeons/screen_protection_api.dart` declares the host API (`setProtectionEnabled`, `isCaptured`, `capabilities`), the messages (`ProtectionCapabilities`, the sealed `CaptureEventMessage`, `SecureLayerFallbackMessage`) and two event channels. Pigeon writes `lib/src/messages.g.dart`, `Messages.g.kt` and `Messages.g.swift`.
- **Generated channel files are committed** (the one exception to "generated code is not committed"), because the native builds need them. CI regenerates them and fails on a `git diff`, so a change of the API without the regenerated files, or a hand edit, cannot be merged.
- **The plugin is a mechanism, the policy is in the application.** The plugin is a workspace member (`workspace:` in `pubspec.yaml`), autolinked by Flutter. `NativeScreenProtection` (`lib/features/documents/infrastructure/native`) implements the port over a seam, `ScreenProtectionModuleApi`, so the adapter is tested with a stand-in and the port's contract suite.
- **One exception to the import rule.** A native view cannot cross a port, so `lib/features/documents/presentation/secure_content.dart` may import `screen_protection_view.dart`, and nothing else of the plugin. `presentationExemptions` in `tool/check_imports.dart` lists that file and that URI, and the checker's tests exercise it both ways.

## Consequences

- The Dart, Kotlin and Swift sides cannot drift apart: a method has one signature and a missing case in a sealed message is a compile error on each side.
- The channel needs no hand-written string names or casts, and the tests of the Dart side run over a fake of the generated host API.
- Pigeon is a build tool to keep in step with Flutter (a dev dependency of the plugin, version 29), and its output is a generated file under version control.
- The native code has the limits of the platforms, which [the native module document](../native-module.md) states: no public way to block a screenshot on iOS, one window for `FLAG_SECURE`, no detection before Android 14 and 15.
- Flutter draws every widget into one surface, so on iOS the secure view marks the whole Flutter view, not the child (React Native marks the layer of the child). While a secure view is mounted, everything Flutter draws is out of captures. It was checked on an iPhone 17 under iOS 27; `FLAG_SECURE` on a real Android window and the Android 14 and 15 callbacks were not checked on a device ([What was verified](../native-module.md#what-was-verified)).

## Alternatives considered

- **A raw `MethodChannel` and `EventChannel`.** No tool, and three hand-kept copies of every method name, argument map and error code; a typo shows at run time on one platform.
- **FFI (`ffigen`, `jnigen`).** Powerful, but the APIs involved are activity and window lifecycle, which are not plain C or JNI calls, and the plugin would carry a second toolchain for a small surface.
- **A community package** (`flutter_windowmanager`, `screen_protector`). None gives protection, the capture events on both platforms and the app switcher cover together, and the module is small enough to own.
- **Dart only.** Impossible for `FLAG_SECURE`, and on iOS the snapshot of the app switcher is taken before Flutter can draw again.
