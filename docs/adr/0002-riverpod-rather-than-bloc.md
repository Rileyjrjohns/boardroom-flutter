# 0002. Riverpod rather than Bloc for state and dependency injection

- Status: Accepted
- Related: [0001](0001-feature-first-hexagonal-architecture-with-links-inverted-through-the-composition.md)

## Context

The React Native app uses TanStack Query for server state, Zustand for the little interface state, and one services context per feature filled by a composition root. The Flutter port needs the same three jobs done: cache and retry the reads, hold the state of an action, and hand each screen the use cases it needs without the screen knowing the adapters. The tool also has to fit the feature graph of [0001](0001-feature-first-hexagonal-architecture-with-links-inverted-through-the-composition.md): a feature must be able to ask for something it does not build.

## Decision

`flutter_riverpod` 3 with `riverpod_annotation` and `riverpod_generator` ([presentation](../presentation.md)).

- **Dependency injection.** Each feature declares its use cases as providers that throw until overridden (`lib/features/<feature>/presentation/providers.dart`, `@Riverpod(keepAlive: true)`). `lib/app/providers/app_overrides.dart` overrides every one with an object built by the composition (`lib/app/container`). A test overrides the same providers over fakes (`TestApp`, `test/support/presentation/test_app.dart`). `test/app/providers/app_overrides_test.dart` reads the `providers.dart` files and fails if a provider that throws is not overridden.
- **Server state.** A read is a provider that throws a `QueryFailure` when the use case returns an error (`unwrapResult`). Retry, back-off and the rule "do not retry a code a second try cannot fix" are the `RetryPolicy` given to the root `ProviderScope` (`lib/core/presentation/query/retry_policy.dart`: two retries after 0.5 s and 1 s, capped at 4 s). `keepQueryFor` (`query_lifetime.dart`) is the counterpart of `staleTime` and `gcTime`: a query is fresh for 60 seconds and kept in memory for 5 minutes after its last listener, and it is registered in a `QueryRegistry`, so `dropQueriesWhenSessionMoves` can drop every query when the user signs out, the app locks or another user signs in.
- **Client state and actions.** A `Notifier` holds the state of an action (`runResultAction`, `ActionState`) or of the little interface state (`lib/core/presentation/state/ui_state.dart`). Actions are not providers and are never retried.
- **Generated providers.** `*.g.dart` files are generated by `dart run build_runner build` and not committed.

## Consequences

- One tool covers what React Native splits across three (TanStack Query, Zustand, the services contexts), and the dependency graph of the providers is checked by the compiler and by the override test.
- Overrides are a good fit for inversion: the composition is the only place that builds an adapter, and a test swaps one provider for a fake.
- The query layer is written here (`lib/core/presentation/query`, about 360 lines), not taken from a library. TanStack Query's behaviours (retry, stale time, dropping the cache on sign-out) are re-created and tested, not inherited. That is a cost, and it is why the behaviour is pinned by tests of the same names as the React Native ones.
- Riverpod 3 and its generator are young. The versions are pinned in `pubspec.yaml`, and the paused-provider behaviour of version 3 forced one design point: the session-moved subscription is on the container, not a `ref.listen` in a query, because a provider nobody listens to is paused and would miss the change.
- A provider that throws is a runtime check, not a compile-time one. The override test is what makes it safe.

## Alternatives considered

- **Bloc / Cubit.** Mature and well known, with a clear event log. It would give a class and a state hierarchy per screen, no dependency injection of its own (it needs `RepositoryProvider` or `get_it` beside it), and no cache or retry for reads, so a query layer would be needed as well. Riverpod's providers cover the injection and the reads with one idea.
- **Provider plus `get_it`.** Smaller, but injection through a global locator is the opposite of an explicit composition, and tests would reset a global.
- **Hand-written `InheritedWidget`s and `ValueNotifier`s.** No dependency, and every cache, retry and disposal rule written by hand for each feature.
- **`flutter_hooks` and `riverpod` without code generation.** Fewer generated files, but the provider names and families are then typed by hand, and the check that no provider is left unoverridden reads the generated names.
